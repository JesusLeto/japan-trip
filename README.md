# Travel Planner

Личный веб-планировщик путешествий. Одна поездка целиком: Япония, Осака → Токио, 14 дней — чеклисты подготовки, маршрут день за днём с картой и планами Б, отели, бюджет и практическая справка.

Всё хранится локально в браузере, бэкенда нет.

## Что внутри

Восемь секций: `/01` До вылета · `/02` По прилёту · `/03` Маршрут день за днём · `/04` Где спать · `/05` Бюджет · `/06` Практика · `/07` Куда не ходить · `/08` Экспорт.

Главная — третья. Это табы дней: клик открывает описание дня (утро/день/вечер, переезды, еда, план Б), а под ним карту с маршрутом того же дня. Описание и карта — две грани одного дня, не отдельные экраны.

## Чем это отличается от списка мест

Маршрут собран не по памяти модели, а по источникам, и каждое утверждение можно проверить:

- **Координаты** — из Nominatim, запрос и ответ записаны в [route-provenance.md](docs/knowledge/route-provenance.md).
- **Пешие и автобусные трассы** — реальная геометрия из OSRM, а не прямые линии между точками. Там, где геометрии нет (рельс, канатка, паром), на карте честная прямая, и это помечено.
- **Факты о местах** — из справочника, на который ориентируется владелец проекта. Он главнее общих знаний модели.
- **Чего источники не подтверждают** — не выдаётся за факт и не удаляется, а лежит списком в [unverified-claims.md](docs/knowledge/unverified-claims.md).

Подробнее про базу знаний и почему её текст не в репозитории — [docs/knowledge/README.md](docs/knowledge/README.md).

## Запуск

```bash
npm install
npm run dev
```

Ещё: `npm run build` (tsc + прод-сборка), `npm run lint`, `npm run preview`.

Две проверки маршрута вне приложения:

```bash
node scripts/check-route.mjs
```

считает длину каждого дня и ловит развороты назад (когда точка в середине даёт крюк);

```bash
node scripts/export-kml.mjs
```

собирает KML для Google My Maps — дни группируются в слои, потому что My Maps берёт максимум десять.

## Стек

React 19 + TypeScript, Vite, Tailwind CSS v4, Leaflet 1.9 напрямую (без react-leaflet). Состояние — Context + `useReducer`, хранилище — `localStorage` за интерфейсом `StorageAdapter`, чтобы его можно было заменить на серверное, не трогая компоненты.
