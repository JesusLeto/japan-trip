## Чего в гите нет и почему

Каталог `wrenjapan/` содержит **70 статей [wrenjapan.com](https://wrenjapan.com/destination/japan/), сохранённых дословно** — они лежат на диске у владельца проекта и работают как источник фактов о поездке, но в репозиторий не попадают: права на текст принадлежат автору сайта, и сохранены они были для личного использования, а не для переопубликации.

В гите остаётся только `wrenjapan/INDEX.md` — собственный указатель по темам с заголовками и ссылками на оригиналы.

Из-за этого в других файлах проекта есть ссылки вида `wrenjapan/gde-selitsya-v-osake.md`, которые на GitHub ведут в никуда. Это ожидаемо: локально они работают, в вебе — нет.

## Как восстановить корпус

Статьи забирались из браузера (сайт отдаёт 403 на `curl`), каждая — в отдельный файл с шапкой:

```markdown
# <заголовок статьи>

- Источник: <URL>
- Дата статьи: <дата публикации>
- Раздел: <раздел сайта>

> Дословный текст статьи, сохранён для личного использования при планировании поездки.
> Права на содержание принадлежат wrenjapan.com.

---

<текст>
```

Имена файлов — слаг из URL статьи, они перечислены в [INDEX.md](wrenjapan/INDEX.md).

## Правило работы с источниками

Если память модели расходится с текстом статьи — **прав текст**. Цифры (цены, курсы, визовые сроки) устаревают: для решений с ценой ошибки открывай ссылку на источник из шапки файла и сверяй.

Утверждение, которого в источниках нет, не удаляется и не выдаётся за факт — оно попадает в [unverified-claims.md](unverified-claims.md).
